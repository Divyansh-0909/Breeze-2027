# Reproducible physical-device acceptance procedure

No physical GPU or phone was available for this review. These steps are a handoff procedure, not completed benchmark results. Preserve HEAD e3dbbc2 and approved layout/lighting/assets.

1. Use a clean production build (`npm ci`, `npm run build`, `npm run start`) with ordinary local configuration. Do not submit real payment/admin/forms during profiling. Record exact revision, OS/browser versions, CPU/GPU/driver, power mode, thermal state, viewport, screen DPR, WebGL debug renderer and effective diagnostic DPR/tier. Use localhost on laptop or an authorized HTTPS preview on phone; protected Vercel preview requires owner access.
2. Prioritize ordinary Intel/Ryzen integrated laptop, modern iPhone Safari and mainstream Android Chrome. Disable DevTools CPU/network throttling. Run each device separately. Record a fresh browser-profile cold load and a subsequent same-profile warm load; retain Resource Timing/Network HAR including cache flags and transfers, not just requests' advertised content lengths.
3. Add `?diagnostics` to the URL; record `window.__gullyverse` frame samples, phase/preparation events, stats and memory payload estimates through a browser console or the report's profiler adapted to a reachable base URL. Do not force DPR/tier down and label it the device's native result. Distinguish rendered frames (finitecpuRenderMs) from covered RAF callbacks. Record raw quality changes.
4. Fresh landing click/tap/Enter → full tunnel → hub → walk forward under scaffold → Aftermovie → Play/Esc → all edges/Stay/rearm/return → aerial ascent/select/exit → information routes/NavbarHome/BackForward. Capture native screenshots and one uninterrupted screen recording separately from FPS runs. Test portrait/landscape, real background/resume, sound/unmute, autoplay restrictions and WebGL recovery.
5. Collect at least30s stable hub movement and30s stage movement; p50/p95/p99 intervals, FPS, stalls>50/100ms, drawcalls/triangles/counters/JSheap and longtasks. Measure actual activation→entrance completion7.2s plus pacing limitations; separate covered compilation/readiness from0.65/0.75s departure/arrival. Record cold and warm travel.
6. Ten Hub↔Aftermovie round trips, then ten movie/play-exit-travel cycles; include early exit, navigation while playing, natural-ended or clearly labeled near-end seek, aborted critical/video asset and recovery. Allow settle, collect post-GC heap where supported and inspect material sampler refs/GL create-delete plateaus. Do not equate JSheap/sourceRGBA estimates/counters with driverVRAM.
7. Target60FPS where feasible; document graceful30FPS on supported constrained devices. Report sustained intervals and thermal degradation. “No visible recurring hitch” requires a real device recording and frame evidence. If a target fails, report it before adding final art. Do not alter approved stage/lighting to conceal baseline cost.
8. Validate one rock-segment pilot at matched baseline poses and original stage hashes before extending production. Define measured tier budgets for triangles, drawcalls, compressed transfer, decoded textures, LODs and optional residency. No broad source cleanup or final-art rebuild is authorized by this procedure.

Local commands/logs/scripts accompany the package. Existing cloud frame/resource numbers are SwiftShader results and must not be compared as equivalent IntelUHD620 hardware measurements.
